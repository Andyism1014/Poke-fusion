# 《宝可梦：绿宝石·炼妖版》V2.0 开发路线

基于 `rh-hideout/pokeemerald-expansion`（基线提交 `f4dc700a`）。

核心目标：**自由合宠 + 多被动特性 + 多属性 + 全局宝可梦管理 + 高效率抓宠**。
V2.0 范围：4 个同时生效的特性（1 主 + 3 被动）、最多 3 种永久属性、任意队伍/盒子随时合宠。
超过 4 个招式、4+ 属性、变异系统放到后续版本。

## 设计原则

1. 合宠的核心是遗传自由度：招式、被动、属性均可跨种族。限制只来自机制兼容、槽位、概率和平衡。
2. 尽量减少重复劳动：抓到即鉴定、自动入箱、随时筛选与合宠。
3. 先保证战斗与存档稳定，再追求更多组合。

## 阶段 03 已完成内容

炼妖终端菜单：**Fuse** / Appraise / Storage / Exit。流程如下：

1. 选父母 1（保留它的格子）。
2. 选父母 2（会被消耗；列表里自动排除父母 1）。
3. 合法性检查。
4. 显示概率预览。预览只列出可能性和概率，确认后才掷骰，因此无法通过反复打开预览来刷结果。
5. 确认后生成子代，播放进化音乐，并显示子代的鉴定结果。

遗传规则（概率都在 `include/fusion/fusion_config.h`，逻辑在 `src/fusion/fusion_genetics.c`）：

| 项目 | 规则 |
| --- | --- |
| 物种 | 50% 父母 1、50% 父母 2 |
| 等级 | 取两者较低的 |
| 性格 | 50% / 50%（继承实际生效的性格，即薄荷修改后的） |
| IV | 每项 50% / 50%；另有 10% 概率额外 +1~3（上限 31） |
| 招式 | 双方招式去重后组成候选池，每个 50% 独立入选，最多 4 个；一个都没入选时，使用该物种的初始招式 |
| 主特性 | 50% / 50%，可以跨种族获得。是本物种的特性时，直接设置对应的特性槽；否则记为覆盖值 |
| 被动 | 候选池是双方的主特性和被动，去重并排除子代主特性；每个 45% 入选，超过 3 个时随机保留 3 个 |
| 第三属性 | 候选是双方的所有属性（物种属性 + 第三属性）中子代物种没有的；有候选时 50% 获得，从中随机取一个 |
| 世代 | 双方较高世代 + 1，上限 31 |
| 精灵球 / 持有物 | 精灵球来自提供物种的一方；子代持有父母 1 的持有物，父母 2 的持有物退回背包 |
| 禁止 | 两者是同一只、蛋、父母 2 是队伍最后一只而父母 1 在盒子里、任一方携带邮件、背包放不下父母 2 的持有物 |

注意：主特性覆盖值、被动、第三属性目前只会被记录和显示，要到阶段 04/05 才在战斗中生效。

测试：`test/fusion/genetics.c`，用 200 个种子批量验证分布、取值范围、去重、可复现性、跨种族覆盖、持有物退回、邮件拦截。
实机脚本：`dev_scripts/fusion_harness/scripts/terminal_fuse.txt`。截图：`docs/fusion/screenshots/phase03_fuse.png`。

## 阶段 04 已完成内容（4a + 4b）

**4a：跨种族主特性**
- `BattlePokemon.fusionAbility` 在开场、换入、`PokemonToBattleMon` 时生效（`GetBattleMonBaseAbility`）。
- `GetMonAbility` 也会读取覆盖值。为了不拖慢 AI，读取时只解密一次（`MON_DATA_FUSION_EFFECTIVE_ABILITY`）。
- 详情页显示的是覆盖后的特性。
- 洗脑、技能互换等机制只作用于主特性，换下场再上场后恢复。
- AI 直接知道跨种族特性（因为它是公开显示的）。

**4b：多特性框架**
- `BattlePokemon.passives[3]` 存放被动特性。
- 压制按单个特性判断（`ApplyAbilitySuppression`）：
  - 胃液压制全部特性。
  - 化学变化气体压制全部特性，但持有者自己的特性不受影响。
  - 破格逐个判断特性是否可被无视。
  - 特性护具保护全部特性。
- 新增接口：`GetBattlerPassive`、`BattlerHasAbility`、`AbilityOrPassiveIs`；`IsAbilityOnSide/Field` 也会检查被动。
- 事件系统：每个特性事件后面都加了一个"被动"步骤，靠 `fusionPassiveSlot` 游标在多次调用间逐个执行被动，覆盖：
  - 入场（一般特性、免疫、化学变化气体、紧张感、天气/场地）
  - 回合末（加速等）
  - 命中后的目标方、攻击方
- 判断类和伤害修正类：用 `FOR_EACH_ABILITY_SLOT` 把同一段 `switch` 依次跑主特性和每个被动。重复的特性只算一次（技术高手不会叠成 2.25 倍）。
- 弹窗：被动发动时显示被动的名字。
- 离场：自然回复与再生力可以同时生效，分两次更新。
- 遗传：`Fusion_CanBePassive` 排除 `cantBeCopied` 类特性（复制、描绘、形态类等）以及 Gulp Missile，这些只能作为主特性。
- 性能：没有被动的宝可梦走原版路径（循环只跑一次），AI 思考时间测试全部通过。

**已验证的被动**
- 主特性与被动同时发动：威吓、日照、电气制造者。
- 加速、漂浮（可被破格无视）、破格被动、胃液压制、储水、粗糙皮肤、技术高手（不叠加）、结实、再生力 + 自然回复、强行。
- 对手的被动同样生效。
- 测试文件：`test/fusion/battle_passives.c`（14 个）、`battle_main_ability.c`（6 个）。
- 测试框架新增 `FusionAbility(x)` 和 `Passives(a, b, c)`。

## 全世代遇敌表改造

- 每个遇敌格子（每张遇敌表的每一条）都会换成第 1~9 世代中的随机宝可梦。
  - 种族值总和与原宝可梦相差不超过 ±15%；找不到合适的就逐步放宽。
  - 进化阶段保持一致（第一阶段换成第一阶段），原作的难度曲线因此保留，101 号道路不会出现烈咬陆鲨。
- 映射规则 = 每份存档的随机种子（`SaveBlock3.fusionWildSeed`）+ 该格子在 ROM 中的地址。
  - 同一份存档里，每个区域出现的宝可梦固定不变。
  - 每次新游戏都会重新随机一批。
- 草丛、水面、碎岩、钓鱼、DexNav、图鉴的分布、电话里的信息都走同一个函数 `Fusion_GetWildSlotSpecies`，所以彼此一致。

## 后期玩法：炼妖塔、碎片商店、转生（New Game+）

**炼妖塔（无尽肉鸽挑战）**
- 进入殿堂后，炼妖终端菜单里会出现 Tower。
- 每层是一场训练家对战，对手队伍是随机生成的，层数越高越强：
  - 等级 = 我方最高等级 + 层数/3 − 2，上限 100。
  - 每 6 层多 1 个被动；第三属性的概率、IV 下限逐层提高；第 5 层起对手带道具。
  - 每 10 层是 Boss：满 6 只，额外 +1 被动，播放冠军战音乐。
- 层与层之间**不回血**。每赢一层可以三选一奖励，其中"回满全队"必出，所以不会被逼进死局。
- 输一场即本轮结束，全队回满。可以随时主动结束本轮。
- 碎片（Fusion Shards）和最高层数永久保存。
- 同一轮的每一层由本轮种子决定，读档重打也是同一个对手。

**碎片商店（Shard Shop）**
- 入口：炼妖塔菜单。New Game+ 的周目里还没进殿堂时，只要手上有碎片，终端主菜单也会出现商店。
- 商品：
  - 被动水晶（Passive Crystal，30）：随机加一个被动；三格已满时重抽最后一格。
  - 属性棱镜（Type Prism，20）：随机换一个新的第三属性。
  - 神奇糖果、王冠、金色王冠、剩饭、生命宝珠、讲究围巾、气势披带、大师球。
- 两种新道具都在背包里对队伍中的宝可梦使用。

**转生（New Game+）**
- 进入殿堂后，在炼妖塔菜单里选 Reincarnate。存档后，回标题画面选 NEW GAME 即可转生。
  - 选 CONTINUE 则照常继续当前世界。转生可以取消。
- 带入新周目的内容：
  - 存档时的队伍（最多 6 只），回到 Lv.5，EV 清零。
  - IV、招式、性格、特性、被动、第三属性全部保留。
  - 初训家改成新的主角，所以没有徽章也会听话。
- 保留碎片和最高层数；遇敌表的种子重新随机，世界焕然一新。
- 每多一个周目：
  - 训练家等级 +10%，并按周目数获得被动（最多 3 个）。
  - 野生宝可梦出现被动的概率 +8%。
  - 以上加成最多叠到第 5 周目。
- 起始菜单在队伍非空时就显示"宝可梦"，转生的队伍在拿到御三家前也能查看。
- 代码：`src/fusion/fusion_tower.c`、`fusion_ngplus.c`、`fusion_items.c`；测试：`test/fusion/tower.c`、`test/fusion/ngplus.c`。
- 调试菜单 Fusion…：
  - "Tower: auto-win toggle"：跳过对战，直接判胜。
  - "Tower: +100 Shards"。

## 招式效果提示

- 战斗中招式名按对当前对手的效果着色：效果拔群为绿色，效果不好为红色，没有效果为灰色。
- 判断会考虑第三属性、漂浮类被动，以及太晶化。
- 高亮招式的 PP 栏仍显示原版符号（◎ / △ / ×）。
- 配置：`B_SHOW_EFFECTIVENESS = SHOW_EFFECTIVENESS_ALWAYS`；颜色定义在 `graphics/battle_interface/text.pal` 的第 5~8 号空闲色。

## 阶段 05 已完成内容

第三属性在战斗中真正生效。

**实现方式**
- `struct BattlePokemon` 新增 `fusionType` 字段，表示永久第三属性，没有时为 `TYPE_MYSTERY`。
- 这个字段在 `PokemonToBattleMon`、战斗控制器的 `REQUEST_ALL_BATTLE` 中赋值。
- 原本把属性重置为"物种属性 + MYSTERY"的地方，第三个槽位改为写入 `fusionType`：开场、换入、形态变化、`RESTORE_BATTLER_TYPE`（Mimicry 还原用）。
- 字段位于 `pp` 之前，所以变身时会一并复制。

| 机制 | 行为 |
| --- | --- |
| 克制 / 免疫 | 3 个属性逐个相乘，可以出现 8 倍；与本身属性重复时不重复计算 |
